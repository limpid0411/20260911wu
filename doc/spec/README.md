## ✍️ 規格維護與撰寫原則

1. **分章節撰寫**：所有新功能或功能調整，必須回寫至對應模組章節中；若為重大全新獨立模組，應新增 `06_...` 等新章節。
2. **以程式碼為準**：型別定義必須引用實際 TypeScript 介面，避免紙上談兵。
3. **業務邏輯完整**：應詳細包含狀態變更規則、防呆條件、計算公式與權限限制。
